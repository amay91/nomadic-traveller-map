# Handoff: Nomadic Traveller Map

**Read this first in a new session.** Then `tasks.md` (status), and `product_spec.md` / `plan.md` as needed.

## What this is
A tiny personal web app: a clickable world map where the user records the countries they've visited and the years they went, plus a status per place (Visited / Lived / Home). The brief's priorities are **lightweight** (zero runtime dependencies, no build, no server, opens by double-click) and **design** (modern minimal, a two-colour map, polished and playful motion). It's a sibling to Pāntha (`D:\Claude\TravelPlanningApp`) but separate. Pāntha plans trips that are coming up; this one remembers trips that have happened. Product name is **Nomadic Traveller Map**; the project folder/files stay `TravelMap` (matching Pāntha's own display-name-vs-repo-name split).

- **V3's performance numbers are real but bounded, and the bound matters:** zero dropped frames / zero long tasks under Chrome's 4× CPU-throttle proxy, on pinch-zoom, pan, the save animation, and hover. That's headless Chromium on this dev machine, not a physical phone — no real GPU/thermal/touch-latency behavior. It's solid evidence the app's own JS isn't doing anything expensive per frame (`apply()`/`sizeToScreen()` write a viewBox attribute and resize ~100 dots — CPU throttling had nothing to reveal); it can't promise the same on an actual three-year-old Android phone. That gap is what V4 is for.
- **⚠ Mobile parity is a first-class requirement (owner directive 2026-09-14, spec §4.7, plan L14).** Mobile had been "accounted for" in the way that produces bad mobile: the persona called the phone *occasional*, §6.4 described mobile as substitutions of the desktop layout, §4.1's performance budget named a *laptop*, and V2's criteria could only catch overflow and tap-target size — nothing in them could fail for being ugly. **Design mobile at phone widths; never derive it from desktop.**
- **How mobile works now** (spec §6.4): the map keeps the whole screen at rest; entry is summoned by a *"+ Add a country"* pill; the popover and panel are bottom sheets, and whichever owns the lower screen makes the resting controls stand down; the table is phone rows with sort chips; press-and-hold peeks a country's name (the touch answer to hover); near-miss taps snap to the nearest place within 22 px.
- **The mobile framing trade-off, so nobody "fixes" it by accident:** at a phone's aspect ratio the map cannot both fill the screen and show the whole world — the world at 390 px wide is a ~180 px strip in a field of blue. Portrait deliberately takes the screen-filling map, framed on the densest cluster of *your* countries (`focusX()`); **landscape gives the whole world edge to edge**, and so does pinching out. This is a stated, documented trade (spec §4.7), not an oversight.
- **⚠⚠ Size budget re-anchored (owner decision 2026-09-14): code EXCLUDING comments, 80 KB ceiling.** It was a flat 70 KB and got breached at 72.0 KB by the zoom-button/pinch-gesture work; rather than raise a flat number a second time, the metric itself was fixed, since 26% of the bytes were comments — exactly the documentation this file leans on. **Raised to 100 KB on 2026-09-15 (owner decision)** — currently **84.3 KB of 100, 15.7 KB of headroom** (`node tools/measure-size.mjs`). It had reached 79.9/80 after E1/E3 (spec F32/F33) took 1.1 KB of the 1.2 KB left, which would have blocked already-agreed work on a number rather than on merit. **What still binds is unchanged:** trace every added KB to a named feature, re-run `measure-size.mjs` after touching `app/`, and comments remain free — never trim one to make a number. The ceiling lives in exactly one place now (`measure-size.mjs`'s `BUDGET`); the docs quote it but the tool no longer repeats it. Comments are still free — never trim one to make a number — but there is very little real-code room left; if the next feature breaches 80, the honest move is asking the owner whether to raise the ceiling (as happened once already) or trim, not quietly shipping over it.
- **⚠ `location.href` is not a real address unless the protocol is `http:`/`https:` (plan L15).** "Email me this map" used to embed it unconditionally and sent a `content://downloads/...` string to a real user's inbox — the STANDARD result of opening the single-file build (`nomadic-traveller-map.html`) via Android's Downloads app, not a rare case. Any code that treats `location.href` as a stable, shareable link needs the same protocol check this fix added, or it will silently produce garbage the moment someone isn't on a real hosted origin.
- **`#list` (the country dropdown) is a body-level element, positioned in JS — never nest it back inside `#entry`.** It used to live inside `.field.combo`, which broke the moment the entry sheet gained `overflow-y:auto` for keyboard-avoidance (§V2b): the dropdown floats entirely above the input, outside the sheet's own clip box, and — confirmed empirically, not just reasoned about — even `position:fixed` plus an explicit z-index wasn't enough to escape that ancestor chain's hit-testing. It's now a sibling of `#entry`, matching `#pop`/`#tip`/`#toast`/`.panel`, repositioned via `renderList()` on every keystroke from whichever element it's anchored to (the combo field on desktop, the whole sheet on mobile — the sheet's own title bar sits above the field, so anchoring to the field alone floats the dropdown over that title).
- **`visits[iso].y` entries can now be `number | {from, to}` (F21, periods for Lived/Home) — `to: null` means ongoing.** Every reader goes through `yearsOf()` plus `formatYearsEdit()`/`formatYearsDisplay()`/`latestYear()` (`logic.js`) rather than assuming a flat number array; if you add a new place that touches `y`, use those, not `.join(", ")` or `ys[ys.length-1]` — both silently break on a period (a comma-join stringifies `[object Object]`; indexing the "last" element for a sort key compares an object to a number with `<`, which is always `NaN`).
- **Map labels (`sizeToScreen()`) MUST use the cached `labelEls` array and the ~20/s throttle — never re-add a raw `svg.querySelectorAll(".lbl")` inside the per-frame path.** Re-querying and restyling all 240 labels every rAF tick during a pinch cost real frame time under CPU throttling (found by re-running V3's own profiling method after adding labels). Also: a reveal rule based only on a place's on-screen width can never reach the smallest real countries (Vatican, San Marino, Monaco are still under the threshold even at this app's 12× zoom ceiling) — they need the zoom-level fallback `sizeToScreen()` already has; don't remove it as "dead code" without re-measuring at max zoom on one of those first.
- **⚠ On a phone (`phone()`, `innerWidth<=640`), map labels are the ISO code at EVERY zoom level, full stop — never re-enable the full-name fit-check there.** The fit-check only asks "does this name fit THIS place's own border"; it has no idea a neighbour's name is about to land a few px away, which is fine on a spacious desktop viewport and guaranteed unreadable on a 390px screen packed with small islands (measured: 178 overlapping full names in the Lesser Antilles before this was added, 0 after). `updateLabels()`'s `wantsCode` checks `phone()` FIRST, ahead of both the zoom-threshold and fit-check rules — keep it there if this logic is ever refactored. There is still no cross-label collision avoidance even for codes, so the tightest clusters (Lesser Antilles on mobile, Balkans on desktop) can still crowd a little; that's a known, smaller residual, not a regression.
- **⚠ Bucket list (`s:"bucket"`) is a FILTER, not a label — the one status that is. Every other place that reads `visits` for a count must actively exclude it, not just fail to include it.** `stats()`, `focusX()` (the mobile home-frame centring), and `renderRows()`'s "of 195" total all changed to skip bucket-list entries explicitly; a NEW piece of code that iterates `Object.keys(visits)` and doesn't check `isBeen(rec)` (logic.js) will silently count/frame/total a place the user hasn't actually been to. `isBeen(rec)` is the one function that answers "does this record represent a real visit" — use it, don't reinvent `rec.s !== "bucket"` inline.
- **⚠ The heatmap's class-to-colour mapping is entirely CSS (`body:not(.heat-off) .c.h1`…`.h5`), and `paint()` only ever toggles `h1`–`h5` classes — it never picks a colour in JS.** That split is what makes the heatmap on/off toggle free: switching `body.heat-off` repaints every place with one class change on `<body>`, no re-render of `visits`. If a future change needs the actual hex for a class in JS (an export feature, say), read it from `getComputedStyle`, don't hardcode the ramp a second time — `--h1`…`--h5` in `styles.css` are the single source of truth.
- **⚠ `HEAT_BINS = [1,2,3,4,6]` in logic.js and the CSS ramp (`--h1`…`--h5`) are two halves of one design and must change together.** `heatClass()` returns 0–5; CSS has exactly five numbered classes (`h1`–`h5`, 0 meaning "no class applied"). Changing the number of bins without adding/removing a matching CSS class — or vice versa — leaves some visit counts with no colour rule to match.
- **`mergeYears()` (logic.js) is entry-bar-only — the popover must keep replacing outright.** The entry bar now folds newly-typed years into what a place already holds (owner report: re-adding a country to add a forgotten year used to silently wipe the ones already on file) and drops exact duplicates. The popover is deliberately NOT touched: it always shows the complete existing list before you submit, so anything typed there is already a fully-informed edit, and merging there too would make it impossible to actually remove/replace a year via the one surface designed for that (J3). If a THIRD entry surface is ever added, decide explicitly which behaviour it gets — don't assume either default. Also: merging only happens when the record's status ISN'T also changing, since a status switch can legitimately need a different-shaped year list (a period replacing plain years, say) and merging the two shapes together would corrupt it.
- **⚠ When tuning ANY opacity/reveal threshold, check contrast at the RENDERED (opacity-blended) colour, not the swatch's full-strength one.** Label contrast was verified at 100% (8.8:1) when the resting opacity actually shipped at 0.7 — which blends down to 4.08:1, under AA, and is exactly why a real user reported "I don't see the labels" right after delivery even though they were technically present. Current opacities (0.9 unvisited / 0.95 visited) were chosen by computing the blended contrast directly, not assumed — re-derive it the same way if these ever change again.
- **⚠⚠ IF THE OWNER SAYS "I DON'T SEE THE CHANGE" AND IT PASSES EVERY CHECK HERE, SUSPECT PERSISTENT CLIENT STATE FIRST — NOT THE CODE.** This happened, cost most of a session, and was diagnosed wrong twice before being found. The service worker was cache-first over a hand-bumped version string; `app.js`/`styles.css` changed ~20 times without the version ever being bumped, so any browser that had loaded the app once served a frozen copy forever, silently. **Every automated check in this project uses a fresh browser context, which by construction has no service worker and no persistent cache — that environment can never reproduce this class of bug.** "Verified in a fresh browser" ≠ "works for the owner." The SW is now network-first (see `service-worker.js`'s own comment for the full reasoning), so this specific failure can't recur — but the general lesson stands for localStorage, IndexedDB, and anything else that persists across visits.
  **There is a SECOND cache layer underneath the service worker, and it bit us too (2026-09-15).** A bare `fetch(e.request)` inside the worker still goes through the **browser's own HTTP cache**, so "network-first" is only as fresh as *that*. `python -m http.server` sends `Last-Modified` with no `Cache-Control`, which invites heuristic caching — the browser reuses a response for a fraction of its age without asking the server. Renaming the app surfaced it: the page, the manifest and a plain `fetch()` all still returned the OLD product name while the file on disk had the new one, and a `cache: "reload"` fetch in the same tab proved the bytes were there all along. Milder than the v1 disaster (time-bounded, self-healing) but it made the worker's own guarantee false. **The fetch handler now passes `{ cache: "no-cache" }`, which forces a revalidation rather than a blind cache read** — an unchanged file still answers 304 and costs almost nothing. Don't remove it as redundant: it is the difference between network-first and network-first-ish.
- **⚠ Any scale/zoom-level THRESHOLD constant must be expressed as a fraction of `maxScale`, never a fixed number.** `DOT_REVEAL` (the zoom-based label-reveal fallback for Vatican/San Marino/etc.) learned this the hard way: fixed at `6`, it worked fine on desktop (max ~16.6) and meant those labels could NEVER reveal on a 390px phone (max ~4.5, back when `maxScale` still varied by platform — see the CEIL_SCALE gotcha below), at any zoom, full stop. Now `maxScale * 0.36`. If a new zoom-dependent effect gets added, derive its threshold the same way rather than picking a number by eye on whatever's already open.
- **⚠⚠ `CEIL_SCALE`/`zoomMin()` (`app.js`, right after `fit()`) is THE zoom ceiling — every other place that used to hardcode `base.w / 12` or `base.w / 6` must call it instead, never recompute its own copy.** `apply()`, `zoomTarget()`, `flyTo()`'s floor (`2 * zoomMin()`), and the label block's `maxScale` (`innerWidth / zoomMin()`) all read it. Historically this app kept letting these drift into separate hardcoded fractions of `base.w` — `apply()`/`zoomTarget()` already had to be kept in sync by hand once (the Svalbard-drift bug), and `flyTo()`'s own copy was never even suspected until it turned out to be the DOMINANT reason clicking a small country never actually framed it closely, on any device (`base.w/6` ≈173 units, wider than most countries' own padded bbox). `maxScale` is now `CEIL_SCALE`, A CONSTANT, on every platform by construction (`innerWidth / (innerWidth / CEIL_SCALE) = CEIL_SCALE` always) — it is no longer "proportional to screen width" the way it used to be; don't reintroduce a platform-varying `maxScale` without also re-deriving every fraction-of-`maxScale` threshold downstream (`DOT_REVEAL`/`DOT_FADE`, `LBL_SPAN`'s approach ratio).
- **⚠⚠ `tools/build-geo.mjs`'s `anchor()` uses `polylabel` (a DEV-ONLY dependency, never shipped — same L2 precedent as d3-geo), not a geographic centroid, and it MUST run against `renderedRings()`, never against freshly-projected raw coordinates.** A centroid can land outside a non-convex country entirely (Croatia's crescent coastline did, just barely, right on the Slovenian border); polylabel fixes that by finding the point farthest from the boundary instead. But polylabel still needs to run on the EXACT SAME rounded geometry `pathOf()` renders — not the true pre-rounding shape — or the smallest real territories (anything under ~0.2 map units, e.g. Monaco/Bermuda/Macau) can get a label point that's correctly inside the UNROUNDED shape and just outside the SAME shape once it's rounded to the 0.1-unit precision the path string actually stores. `renderedRings()` is the one shared source of truth for both; don't let `pathOf()` and `anchor()` diverge back into two independently-rounded near-copies of the same country. `tests/data.test.mjs`'s "every anchor is INSIDE its own shape" test is the regression guard — it runs real point-in-polygon math against the shipped path for all 171 non-dot places, and it's the check that would have caught the original bug directly. It deliberately SKIPS places in `GEO.d` (dots): their `GEO.c` path can be a genuine zero-area sliver the app never draws (rendered as a `<circle>` instead, per `renderMap()`), and "inside the polygon" isn't a meaningful question for a shape with no real interior.
- **⚠⚠ The global `resize` listener (`app.js`, bottom) must NOT call `apply(home())` unconditionally — check `atHome(view, home())` first, or closing anything with a focused input silently zooms the map back out.** On a phone, a `resize` event doesn't only mean the device rotated: the popover (F4) is a bottom sheet with a focused text field, and dismissing the on-screen keyboard on close fires `resize` too (owner report 2026-09-15: "click close, the map resets back to zoomed out" — this is why). The handler now only snaps to `home()` if the view was ALREADY at home before the resize; otherwise it reclamps the SAME view through `apply()` instead, preserving the zoom. `atHome(v, hm)` is the one shared divergence check — also used by `#reset`'s (the recentre button's) own show/hide toggle in `apply()` — so don't add a second copy of the 3%/5% threshold math. **Guard `Number.isFinite(view?.w)` before trusting `view` in any code that runs this early**: `view` is `undefined` until boot's own first `apply(home())` at the very bottom of the file has run, and `innerWidth`/`innerHeight` can briefly read `0` during initial layout (seen live in headless mobile-viewport testing), which sends `view.w` to `NaN` — and since comparisons against `NaN` are always `false`, an un-guarded `atHome()` reads that as "diverged" and would latch the broken view in place forever rather than self-healing on the next resize.
- **⚠⚠ Every colour is a SEMANTIC TOKEN and lives in CSS — never a literal, and never in `app.js`.** There are now two measured palettes (Atlas and Atlas Night, spec F34 / plan L17), so a hardcoded colour is not a style nit, it is a bug in one of the two schemes that nobody sees until they switch. The theme was hard to add for exactly this reason: 55 colours were hardcoded, and **one `#fff` was doing two opposite jobs** — an inverting *surface* (`--panel`: panel, inputs, table headers) and non-inverting *text on the ink button* (`--on-ink`). If a new value doesn't obviously belong to an existing token, add a token with both scheme values rather than reaching for a hex. **`app.js` holds no palette facts**: because the dark ramp inverts, which heat class needs light versus deep label ink also inverts, so labels carry `h1`–`h5` classes and CSS resolves the ink per scheme. Don't move that decision back into JS. **And measure, don't eyeball** — the scratch tool that produced F34's figures was validated by first reproducing the light-mode numbers already in §4.2; note while you're there that F27's own ΔE scale could not be reproduced (it reports 12.0 where CIEDE2000 gives 21.2), so quote light and dark on one consistent metric or the comparison means nothing.
- **⚠ A throttled per-frame update (label opacity/text, or anything similar) MUST include a trailing call, or a one-shot `animateTo`/`flyTo` can permanently strand it.** A plain time-gate (`if (now - last > N)`) silently drops whatever update would have landed inside the window — fine for a continuous gesture (another update follows almost immediately), but a quick, single-frame settle has nothing to correct it afterward, leaving stale state until some unrelated later interaction happens to fix it. `sizeToScreen()`'s label pass now schedules a `setTimeout` trailing call whenever an update is skipped, guaranteeing the final state is always eventually applied. Any FUTURE throttled per-frame work in this codebase needs the same pattern, not just a bare time-gate.
- **Pointer handling is a pan gesture and a pinch gesture, deliberately kept separate** (`app.js`, "pan / pinch / wheel"). One handler that just counts pointers per move had four bugs — most importantly `moved = false` firing on the *second* finger's pointerdown, which let a short pinch end as a click and open a country's popover. If you touch this code: a pinch must set `gestureClick` so the trailing click is swallowed, and dropping from two fingers to one must re-seed the pan against the **current** view or the map jumps.
- **⚠ Test fixtures count as publishable content — invent them.** Four fixtures in `tests/logic.test.mjs` carried the owner's real residency timeline and survived the D0 privacy scrub purely because that scan covered `.md`/`.html`/`app/` and never looked at `tests/`. Caught while staging the first push to a public repo. **Before any publication step, enumerate what will actually ship (`git ls-tree -r HEAD`) and scan THAT list — not a set of file extensions recalled from memory.** And if personal data has already been committed, rewrite the history rather than adding a scrub commit on top; a follow-up commit leaves the original permanently readable.
- **⚠ Never let real personal specifics back into `docs/design-studies/01-map/index.html`'s `SAMPLE` fixture, or the narrative in `product_spec.md` §5.4 / `tasks.md` / `NOTES.md`.** These were scrubbed 2026-09-14 (`tasks.md` Phase 3, D0) specifically because this repo is going public on GitHub Pages — they used to contain the owner's actual real residency years, a real personal file path, and a specific city, none of which belongs in a public repo. If real data is ever used again for a demo/fixture in this project, treat "will this repo stay private?" as a question to ask before committing it, not after.
- **A table row is the ONLY route to Remove for an already-saved country** — the map is deliberately mouse/touch-only, but that's fine because typing reaches every country; removal has no other path, so rows must stay keyboard-operable (`tabindex="0"` + Enter/Space via `openRow()`). Don't strip that if the table markup changes.
- **`trapTab(container, e)`** contains Tab inside the popover and panel while either is open. Any new modal-ish overlay should call it the same way rather than reinvent the cycling logic.
- **`--kb` (keyboard height) is tracked once, on `<html>`, for every docked bottom sheet — not per-sheet.** The first version tracked it only for the entry bar and zeroed it whenever the bar was closed, which is exactly the state a country's popover is in when its own keyboard needs avoiding — so the popover's input got covered by the keyboard while the entry bar's didn't. If a new bottom-docked sheet with an input is added: if it hides via `opacity:0` when closed (like `.pop`), give it `bottom:var(--kb,0px)` directly. **If it hides via a `translateY` transform sized to its own height (like `.bar`), the keyboard offset must only apply once the transform is cancelled** — put `bottom:var(--kb,0px)` on the `.open`/`.up` class, not the base rule, or a keyboard open for a *different* sheet will drag this one's dismissed state back into view (this exact regression happened and was caught before delivery).

## Gotchas
- **The two Phase-1 bugs above** — read them before touching `logic.js`/`app.js`.
- Service workers refuse to register on `file://` — testing the PWA/offline path needs a real `http://` origin (`localhost` counts as secure). The rest of the app works fine from a double-clicked `file://` file.
- To click a real point on an odd-shaped or small place reliably in a test, project `GEO.a[iso]`'s centroid through the SVG's own CTM (`svg.createSVGPoint()` + `getScreenCTM()`), not a DOM `getBoundingClientRect()` center — for a multi-island shape the bounding-box center can land in open water.
- **A country choice via the dropdown/Enter calls `flyTo`, which moves the camera** — if a test computes a second country's screen point right after that without resetting the view, the projection is meaningless (this cost real debugging time once). Click `#reset` (or check `.reset.show`) before computing the next screen point.
- **Mobile's "home" view is a deliberate crop, and since V2 it is also *adaptive*** (`focusX()`, spec §6.4): it frames the densest cluster of the user's own visits, so **the resting view depends on the saved data**. Two consequences for tests, both of which have already cost debugging time: a country outside the frame is off-screen at rest *by design* (tapping it will genuinely miss — use one the frame shows, or `flyTo` first), and **seeding a different set of visits moves the frame**, so seed before framing assumptions, not after. Adding your first country also re-centres home on it, which is intended.
- **`.x` (the close buttons) is `position:absolute` — never give it `position:relative`.** A V2 touch-target rule did exactly that and silently dropped the popover and panel close buttons out of their corners into the flex flow. `::after` hit-area padding works on it as-is, because absolute is already a positioned ancestor.
- **Anything pinned to the bottom of a phone screen must stand down for the bottom sheets.** The add pill, reset button and counts pill hide under `body.entry-open` / `body.pop-open`; a new bottom-anchored control needs the same treatment or it will float over the popover's Submit button (which is exactly what happened in V2 before it was caught in a screenshot).
- `world-atlas` has **no Tuvalu** (below 1:50m resolution) — hand-placed dot. **Svalbard** looked like the same kind of gap but wasn't — its coastline is in the data, fused into Norway (`plan.md` §2); don't assume "not drawn separately" means "not present" without checking the raw feature's polygon centroids.
- **A label has two states, and the zoomed-out one is the code.** Below `NAME_FROM` (2× zoom from the resting frame) every place shows its three-letter code regardless of fit; above it a shape earns its full name only once that name fits its own on-screen extent. Dot-marker places follow the first rule but can never be fit-checked by the second. Don't "fix" a code showing at world view — that's the design.
- **⚠ The entry bar and the country popover must offer the SAME choices.** The Visited/Lived/Home picker lives in both, painted by one `paintStatus()` — if you add a field to one, ask whether the other needs it, or the two ways of adding a country stop being equivalent. That is exactly how Lived and Home ended up click-only (and therefore keyboard-unreachable) until 2026-09-15.
- **⚠ A country can be resolved WITHOUT going through `choose()`** — typing a full name and pressing Submit matches it exactly, with no dropdown selection, and the blur handler resolves it too. Any state that `choose()` sets up (the status picker, prefilled years) must be handled on those paths as well, or it silently stays at its default. Note also the dropdown is wired to **mousedown**, not click, so `el.click()` in a test does not select a row — it falls through to the exact-name path instead, which looks like the same thing and isn't.
- **`--barW` is the entry bar's width AND the anchor for `#clearMap`/`#emailMap`.** Those two buttons sit just outside the bar's edges via `calc(50% + var(--barW)/2 + 10px)`, so changing the bar's width moves them correctly and changing it to a literal breaks them. The `100vw - 440px` term isn't padding — it reserves the room the flanking buttons plus the corner chrome need, so the bar yields as the window narrows instead of pushing Save under the zoom column.
- **⚠ The bottom edge is crowded, and `.zoom` is 88px tall, not 44.** It's a column of two buttons, so on a phone it occupies the left edge up to 104px from the bottom — the counts-pill row at 74px only *looks* free on the left. Before adding anything to the bottom edge, measure the rectangles of every control there (bar, zoom, reset, add pill, counts pill, `#clearMap`, `#emailMap`) and check every PAIR for overlap, at 360/390/430/660/700/900/1024/1280/1440/1920. That check found a 44×30px collision in the first attempt at this, and separately found that the counts pill had been **overlapping the entry bar at every width below ~1150px** since V2 — which only tested 360/390/430 and 1440, so nothing could have failed. **Also probe the states a static sweep misses:** `#reset` is invisible until the view moves, and both bottom sheets are supposed to make the resting chrome stand down.
- **Label sizing has two constants that must track code elsewhere.** `LBL_SPAN` (in `labelPx`) mirrors the 12× zoom range `apply()` clamps to — change one and the ramp stops reaching its intended maximum at the ceiling. And `nameW` is measured once at boot at a **reference font-size of 10 user units**, so any width estimate derived from it has to carry the live font size (`nameW × fpx / (10 × scale)`); the older `nameW / scale` form was only correct while the font was pinned at 10px.
- **`restWidth()` caches `home().w` against the viewport size, which is only safe because home's WIDTH doesn't depend on the saved visits** — `focusX()` reads them, but only to pick the frame's horizontal centre. If home's width ever becomes data-dependent, that cache goes stale silently and labels get sized against a frame the app no longer rests at.
- **A phone is not "desktop with less zoom" — it reaches a lower maximum *scale*, and anything tuned against desktop's range will mis-size or never fire there.** This has now caused two separate defects: a dot-reveal threshold a phone could never reach (V4 round 3), and label endpoints a phone shouldn't reach (V4 round 5). Express any zoom-dependent constant against a fixed span or a fraction of the platform's own maximum, then **look at a phone-width render** — both bugs were invisible in the numbers and obvious in the screenshot.
- **The zoom-toward-cursor math must clamp before computing the recentring offset**, not after (`plan.md` §3) — found scrolling past the zoom cap near Svalbard; the view drifted steadily away from the cursor otherwise.
- `topojson-simplify`'s `quantile(topo, p)` returns the weight that **keeps a fraction p** of vertices, not the p-th weight from the bottom.
- Natural Earth folds French Guiana, Guadeloupe, Martinique, Réunion, Mayotte into France, and Bonaire+Sint Eustatius+Saba into the Netherlands — all split off at build time in `tools/build-geo.mjs`, and **Sint Eustatius/Saba need their own anchor point**, separate from Bonaire's (one anchor per territory mis-attributed them into Guadeloupe once already).
- **Territories are first-class in the geometry pipeline**, not a special case — `build-geo.mjs` groups every raw feature into `countries` / clickable `extras` / inert `territories`, with one shared placement function so nothing silently vanishes the way three real places once did.
